🤖 coletor-diario

Robô que coleta dados de dois sites todo dia às 6h, guarda no PostgreSQL, registra cada execução e avisa no Discord quando algo dá errado, inclusive quando "dá certo" mas traz bem menos dados que o normal.

Demonstração. Esta página não acessa os sites nem o banco. A extração abaixo foi feita pelo código Python de verdade sobre páginas salvas (as mesmas dos testes automáticos). A regra de anomalia é uma cópia em JavaScript, conferida contra o Python ao abrir a página.

O robô "deu certo". Mas veio certo?

Se o site muda o HTML, o robô não quebra: ele roda até o fim e traz 3 itens em vez de 1.000. Sem uma regra olhando o volume, ninguém percebe. Teste a regra com um cenário pronto ou mexa nos números.

Regras: nenhum válido = falha; mais de 10% inválidos = parcial; menos de 3 execuções no histórico = aceita e vai formando a base; abaixo de 50% da média = parcial. Parcial e falha mandam aviso no Discord.

Extração das páginas

Cada item extraído passa por validação (Pydantic) antes de ir para o banco. Item com campo faltando é contado como inválido, com o motivo, e entra na conta dos 10%.

Como funciona

AgendaGitHub Actions dispara coletor executar --todas todo dia às 06:00.
ColetaLivros com httpx (página estática). Citações com Playwright, porque o texto só aparece depois do JavaScript.
ValidaçãoPydantic confere cada item. Com erro de rede, tenta de novo com espera crescente.
GravaçãoPostgreSQL: itens, histórico de preço e uma linha por execução (status, tempo, motivo).
AnomaliaCompara o volume de hoje com a média recente (simulador acima).
AlertaParcial ou falha vira mensagem no Discord, com print da tela quando foi o navegador que falhou.

Uma API somente leitura (FastAPI) entrega as execuções para o Painel de operação.
